# Integration status — what is real, simulated, or future

| Area | Working locally (real logic) | Simulated (labelled in the UI) | Future authorized integration |
|---|---|---|---|
| Identity & roles | Persona session cookie (HMAC), server-side ownership/role checks on every route | Persona switching (demo control only, `DEMO_MODE=true`) | University SSO |
| Course registration | Prerequisite/co-requisite/duplicate/overlap/capacity/credit-limit/travel-gap checks, option generation, explicit approval bound to payload hash + revision + expiry + idempotency key, atomic mock commit, timeout reconciliation, calendar + transcript updates on confirmed success | EduGate submission (`UniversityPortalAdapter` demo provider with operation IDs, stale capacity, timeouts, partial results) | EduGate connector implementing the same adapter interface (no public API was verified) |
| Attendance & excuses | Exact-session binding, evidence ownership, text-layer extraction with editable preview, student approval, reviewer queue with needs-information, configurable attendance treatment | EduGate excuse submission + request IDs; the Sehhaty report is a synthetic PDF; OCR for images is not bundled | EduGate excuse API; Sehhaty document verification (never claimed) |
| Study planner | Natural-language intake (rules), capacity/deadline scheduling, minimal-movement repair, locked tasks, infeasible reporting, plan versions with execution history | Optional model-backed parsing (`AIIntentAdapter`) — deterministic rules by default | — |
| Clubs & events | Membership states, lead approvals, capacity/waitlist, RSVP → one calendar entry, class-conflict detection, excuse/study links, achievements after verification | External hackathon/competition listings are demo records with provenance fields | Official event feeds |
| Learning resources | Search/filter/sort, preview/download, uploads with rights confirmation and moderation, bookmarks, helpful votes, study-task links | Extractive summaries (AI summaries only with a key, citing paragraphs) | — |
| Campus navigation | Riyadh layer rebuilt from the annotated YU campus map (5 gates, Najd/Tuwaiq/Main buildings, rooms, parking, sports, residence) georeferenced to OpenStreetMap footprints and paths (≈2 m); walkways traced where OSM has none; routes never cut through unrelated buildings; map/satellite base layers; Dijkstra routing with walking/accessible modes; unreachable destinations reported honestly; Google Maps tiles when `GOOGLE_MAPS_API_KEY` is set (OpenStreetMap otherwise) | Khobar campus centre (Al Sadafah district) is approximate with a synthetic layout; building purposes/rooms and accessibility attributes are unverified | Surveyed geometry, indoor maps |
| Lost & found | Owner-bound requests, opaque IDs that reveal nothing without authorization, security queue, found-item matching (suggestion only), staff-confirmed handover, owner-only notifications | Email delivery (rendered into an outbox preview) | SMTP / notification provider |
| Career | Explainable matching, dedupe by normalized URL/source id, one application per opportunity, attested "applied", status history, interviews → calendar with conflicts, email review queue with no downgrades | Opportunity feed refresh, hiring emails, autofill draft ("not submitted") | Job-board APIs, Gmail read-only sync with scoped consent |
| Admission & graduation | Checklist completeness, demo receipts, officer/registrar decisions, same-profile transition to student, degree audit that never counts planned/enrolled credits | Decisions by demo personas; admission criteria are illustrative | Admission system, official degree-audit source |
| Notifications & documents | In-app inbox, private document store with magic-byte validation and per-module access grants | Email outbox | — |

Secrets stay server-side (`.env`); the client only learns whether Google Maps is configured. No crawler, mailer or
external submission runs in the prototype.
